11+## Windows
12+ 
13+HLSL shaders are embedded as source and compiled on first use with `d3dcompiler_47.dll`
14+(`D3DShaderCompiler`), which is part of every Windows 10/11 install, so no shader toolchain
15+is needed to build or run. Compiled bytecode is cached for the lifetime of the process.
16+Compile errors are thrown as `InvalidOperationException` with the compiler output.
17+ 
18+The desktop build only targets `net10.0` on Windows. To also build the Android/iOS targets
19+there (with the workloads installed), pass `-p:CrossXMobileTargets=true`.
20+ 
21+The GPU device is created with SDL debug mode first; if that fails (for example when the D3D12
22+debug layer from the optional "Graphics Tools" Windows feature is not installed) it retries
23+without debug mode.

25+## Writing shaders
26+ 
27+Each pipeline/effect has a Metal and an HLSL version with the same resource name, e.g.
28+`Pipelines.TextureLight.frag` maps to `Metal/Pipelines/TextureLight.frag.metal` and
29+`HLSL/Pipelines/TextureLight.frag.hlsl`. When you change one, change the other.
30+ 
31+HLSL rules imposed by SDL GPU on Direct3D 12:
32+ 
33+- Vertex attributes use semantic `TEXCOORD{location}` (location as in `SDL_GPUVertexAttribute`).
34+- Vertex stage: textures/samplers in `space0`, uniform buffers in `register(bN, space1)`.
35+- Fragment stage: texture/sampler N in `register(tN, space2)` / `register(sN, space2)`,
36+ uniform buffers in `register(bN, space3)`.
37+- Entry points are `vertexMain` / `fragmentMain`.
38+- Uniform matrices come from `System.Numerics.Matrix4x4`; with HLSL's default column-major
39+ packing use `mul(transform, position)`, matching `transform * position` in Metal.
